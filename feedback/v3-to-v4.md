# v3 → v4 反馈

> 被评估对象：`output/v3/generated.md`（20 项结构检查全部通过）
> 结论一句话：**v3 把"形状"锁死了，但形状对了不等于内容对。剩下的毛病全在"这个词到底该叫什么、这个数到底是哪个长度"上——结构规则一条都管不到。**

## 一、v3 做对了什么（先说清楚，免得 v4 把好东西改坏）

| 项 | 结果 |
|:---|:---|
| C1–C12 | 20/20 通过（`tmp/check_v3.py`） |
| 层级 | 4 层，可复算 |
| §5 评价 | 两份评价都含"第 N 轮 / 漏掉什么 / 下一步补什么" |
| §6 排查 | 问题 1/2/3 分别 2/3/3 条命令，且每条都有"排除了什么" |
| 真实性表 | 24 行，每行都能 `sed -n` 复核 |
| 字数 | 各节都在区间内 |

**v3 的验收条件表要原样保留，v4 是在它之上加一层，不是替换。**

## 二、v3 输出仍然存在的问题（带行号证据）

### 问题 1：同一个概念三种叫法

| 位置 | 写法 |
|:---|:---|
| `:11` | "哈希与认证" |
| `:55` | 小节标题"### 四、哈希与认证" |
| `:94` | 导图节点"哈希与MAC" |
| `:59` | 正文"**消息认证码**（MAC）" |

"认证"是个边界极模糊的词（可以是 MAC、可以是数字签名、可以是口令校验），而"消息认证码"是有准确定义的术语。同一份报告里三种叫法，读者没法判断我知道不知道它们的区别。

这是**结构检查永远抓不到**的问题：三种写法都满足"节点 ≤12 字""章节齐全"。

### 问题 2：§3 反思了，正文却没改

- `:75` §3 问题 3 明确写了："AI 说'SM2 的定位类似于 RSA'……SM2 是**椭圆曲线**密码，和 RSA 的数学基础完全不同"。
- 但 `:53` §2 正文里那句"SM2 是国密体系里的公钥算法，它的定位类似于 RSA"**原封不动留着**。

v3 的 C5 只要求"§3 引用 §2 的原句"，**没要求改 §2**。于是反思和正文各说各的，一份报告自己打自己的脸。这是 v3 规则设计上的漏洞，不是执行不力。

### 问题 3：数值只写了一半

`:47`："AES 支持 128/192/256 位密钥，是目前的主流。"

- 这是**密钥**长度，但 AES 的**分组**长度恒为 128 位，报告没说；
- SM4 的分组/密钥长度（128/128）是在 §3 反思里补的，§2 正文没写；
- 全文没有统一约定"提到一个分组密码，就要写清分组长度和密钥长度"。

对照：v3 自己在 §3 问题 1 里承认"我第一版草稿按 DES 的习惯写成了 64 位"——说明我本来就知道这个坑，但没把它变成写作规则。

### 问题 4：没有术语表，核心概念缺失

- 全文没有任何一处集中说明"本报告用了哪些术语、每个是什么意思"；
- `grep -c '混淆\|扩散\|密钥空间\|攻击模型'` = **0**。教材第 1 章讲对称密码必讲混淆与扩散、讲密码系统必讲密钥空间和攻击模型，一个都没出现在报告里。

阅卷人看完 4000 字，无法快速确认"这些术语他到底懂不懂"。

## 三、给 v4 的 6 条硬要求

沿用 v3 的写法：每条都必须带判定方法。

### T1 术语表（新增附录 C）

- 要求：附录 C 是一张表，≥10 行，列为 `术语 | 一句话定义 | 易混术语与区别 | 出处`。
- 判定：`grep -c '^| ' 附录C` ≥ 11（含表头）；"易混术语与区别"列非空率 100%；"出处"列只能是 `教材第 X 章「节名」` 或 `handmade/lab/logs/*.log:N`。
- 不达标表现：术语表里写"RSA：一种加密算法"（没有区别、没有出处）。

### T2 全文术语唯一

- 要求：同一个概念全文只用一个中文主名；首现写"中文名（英文缩写）"，之后不再混用别名。
- 判定：为每个概念建别名组（如 `消息认证码/MAC/报文鉴别码/认证码`），全文中每组只能出现主名 + 首现的括号缩写。
- 不达标表现：`:11` "认证"、`:55` "认证"、`:94` "MAC"、`:59` "消息认证码" 四种写法并存。

### T3 禁止用类比代替定义

- 要求："类似于 / 相当于 / 差不多 / 可以说就是 / 本质上就是"不得用于给术语下定义。
- 判定：`grep -nE '类似于|相当于|差不多|可以说就是|本质上就是'` 命中的行，若该行含"是……的算法/机制/函数"这类定义句式，判不合格。类比只能出现在"辅助理解"段落，且后面 1 句内必须出现"但区别在于"。
- 不达标表现：`:53` "它的定位类似于 RSA"。

### T4 数值三件套

- 要求：提到任何一个分组密码 / 哈希函数，必须写全：分组长度、密钥长度（哈希无密钥则省略）、输出长度、单位。
- 判定：每个算法名第一次出现的那句话里，`分组` 与 `密钥`/`输出` 两个词必须同时出现，且都紧跟 `\d+ ?位`。
- 不达标表现：`:47` 只写了 AES 的密钥长度。

### T5 教材概念覆盖

- 要求：术语表必须覆盖本章的"骨架概念"，本课程第 1 章固定要求 6 个：密码与口令、柯克霍夫假设、混淆与扩散、密钥空间、攻击模型、混合密码系统。
- 判定：这 6 个词在术语表"术语"列中全部出现（允许措辞微调，但必须能一一对上）。
- 不达标表现：`grep '混淆\|扩散\|密钥空间\|攻击模型'` = 0。

### T6 反思必须回写正文

- 要求：§3 每条问题指出的错，§2 正文里对应句子必须已经改过；§3 保留原句是为了说明"AI 原来错在哪"，正文不能同时保留错误说法。
- 判定：把 §3 引号里的原句拿到 §2 里 `grep -F`，**命中数必须为 0**（改了之后原句理应只在 §3 出现，且 §3 里必须带"AI 说"前缀）。
- 不达标表现：`:53` 与 `:75` 同时存在同一句错话。

## 四、v4 不要做的事

1. **不要**为了凑术语表去堆没出现在正文里的术语——术语表里的每个词都必须在正文出现过至少一次（判定：术语名在正文中 `grep -c` ≥ 1）。
2. **不要**把 v3 的 C1–C12 删掉或放宽。
3. **不要**把术语表做成"背定义"——"易混术语与区别"这一列才是重点，写不出区别就说明没懂。
4. **不要**引入外部教材原文（我手上没有电子版教材），术语定义一律以"我自己的话 + 国标名称"为准，不许编造页码。

## 五、v4 的验收方式

1. C1–C12 仍然全过（不能因为加术语表把章节弄乱）；
2. T1–T6 六条逐条判过；
3. 人工抽查：从术语表里随机挑 3 个，问"它和旁边那个词差在哪"，答不上来说明术语表是抄的。

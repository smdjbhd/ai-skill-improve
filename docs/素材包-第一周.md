## 一、第一章：密码学基础（概念复习）

### 1.1 先把「密码」这个词掰开

| 说法 | 含义 | 常见误用 |
|:---|:---|:---|
| 密码（cryptography） | 研究信息保密与认证的技术体系 | 以为等于"加密算法" |
| 口令（password） | 身份鉴别用的字符串 | 日常说"设置密码"，其实是口令 |
| 密钥（key） | 算法中参与运算的秘密参数 | 以为密钥越长越安全（还要看算法与实现） |

写报告时要注意：**教材里的"密码"是学术义，不是"登录密码"**。这一条我在写"反思与补充"时可以用来批评 AI 总结（AI 经常混用）。

### 1.2 密码系统的五元组

一个密码体制由五部分组成：

- 明文空间 **M**
- 密文空间 **C**
- 密钥空间 **K**
- 加密算法 **E**: M × K → C
- 解密算法 **D**: C × K → M

对称体制：加密密钥 = 解密密钥（或可互相推出）；非对称体制：加密用公钥、解密用私钥，两个密钥不能互推。

### 1.3 四个安全属性（写报告时用来撑"概念完整性"）

1. **机密性**（confidentiality）——只有授权者能读
2. **完整性**（integrity）——数据没被篡改（注意：哈希能查篡改，但不防篡改，因为没有密钥）
3. **认证性**（authenticity）——确认对方身份/数据来源
4. **不可否认性**（non-repudiation）——发送方事后不能抵赖，**只有数字签名能做到，MAC 做不到**（因为 MAC 的密钥双方共享）

这一条是后面苏格拉底提问的引子：MAC 和签名都"防篡改"，区别就在密钥是否对称、能否抵赖。

### 1.4 分类树（画思维导图时直接抄这棵树）

```
密码体制
├── 对称密码
│   ├── 分组密码：DES / 3DES / AES / SM4
│   └── 流密码：RC4 / ZUC（祖冲之）
├── 非对称密码
│   ├── 基于大整数分解：RSA
│   ├── 基于离散对数：DH / ElGamal
│   └── 基于椭圆曲线：ECC / SM2
└── 哈希与认证
    ├── 哈希：MD5 / SHA-1 / SHA-2 / SHA-3 / SM3
    ├── MAC：HMAC / CMAC
    └── 数字签名：RSA-PSS / ECDSA / SM2
```

补充：实际系统几乎都是**混合体制**——用非对称算法传对称密钥，用对称算法加密数据（TLS 1.3 就是这样：ECDHE 协商 + AES-GCM 传输）。

### 1.5 攻击模型（容易背混，列表记）

- **唯密文攻击**：只有密文
- **已知明文攻击**：有若干明文-密文对
- **选择明文攻击**（CPA）：能自选明文让系统加密
- **选择密文攻击**（CCA）：能自选密文让系统解密
- **相关密钥攻击**：密钥之间有已知关系

安全目标：CPA 下不可区分（IND-CPA）、CCA 下不可区分（IND-CCA）。**流密码/分组密码的工作模式如果没加认证，通常只能到 IND-CPA**——这是 AES-CBC 需要再加 HMAC 的原因，也是 GCM 流行的原因。

### 1.6 国密算法对照表（第二章用得上，也常被考）

| 算法 | 类型 | 关键参数 | 对应国际算法 | 标准 |
|:---|:---|:---|:---|:---|
| SM1 | 分组密码 | 128 bit 分组/128 bit 密钥，算法不公开，硬件实现 | AES | 商密 |
| SM2 | 椭圆曲线公钥 | 256 bit 曲线，签名/加密/密钥交换 | ECDSA/ECDH + RSA | GB/T 32918 |
| SM3 | 哈希 | 输出 256 bit，Merkle-Damgård 结构 | SHA-256 | GB/T 32905 |
| SM4 | 分组密码 | **128 bit 分组 / 128 bit 密钥**，32 轮 | AES | GB/T 32907 |
| SM9 | 标识密码（IBC） | 以身份标识为公钥 | — | GB/T 38635 |
| ZUC | 流密码 | 祖冲之，4G/5G 空口加密 | RC4 | 商密 |

易错点：
- SM4 分组长度是 **128 bit（16 字节）**，不是 64 bit——AI 常写错；
- SM3 输出 256 bit，和 SHA-256 同长度但**结构不同**（SM3 有 P0/P1 置换和不同的压缩函数），不能互相替代；
- SM2 是**椭圆曲线**，不是"RSA 的国密版"；
- SM9 是标识密码，和 SM2 不是一个体系，应用场景也不同。

### 1.7 法规与标准（报告里提一句就够，别展开）

- 《中华人民共和国密码法》2020-01-01 施行：密码分为核心密码、普通密码、商用密码
- 《商用密码管理条例》2023 年修订
- GB/T 39786—2021《信息安全技术 信息系统密码应用基本要求》——"密评"的依据
- 密评：商用密码应用安全性评估，"三同步"（同步规划、同步建设、同步运行）

## 二、第二章：在 Linux 上把 OpenSSL / GmSSL 更新到 3.x

### 2.1 为什么要自己编译

Ubuntu 22.04 自带 OpenSSL 3.0.x，openEuler 22.03 自带 3.0.x 或 1.1.1；教材要求 3.0 以上且要能用 SM2/SM3/SM4 与 provider 相关命令，所以按脚本编译 3.3.2 并覆盖系统库。

### 2.2 脚本逐段读（这个脚本是老师给的，但要能讲清楚每一段在干什么）

1. `VER=3.3.2`、建三个目录：`rocopenssl`（安装前缀）、`rocopensslsrc`（源码）、`rocopenssldir`（openssldir，放 openssl.cnf）
2. 下载源码 tar.gz → 解压到 `rocopensslsrc`
3. `./config --prefix=... --openssldir=...` → `make` → `sudo make install`
4. 判断 `uname -a` 里有没有 `ubuntu` 或 `WSL`：
   - 备份 `/usr/lib/x86_64-linux-gnu/libcrypto.so.3`、`libssl.so.3` 为 `*.rocbaknewopenssl`
   - 把新编译的 `libcrypto.so.3`、`libssl.so.3` 软链到系统目录
   - 备份 `/usr/bin/openssl` 为 `/usr/bin/opensslbak`，再软链新的
5. `openssl version` 验证；删压缩包

**这一步的风险**（写"问题与解决"时用）：替换了系统的 libssl3，`apt`、`curl`、`ssh` 都依赖它，一旦新库缺符号或 ABI 不兼容，系统包管理会崩。

### 2.3 我要在自己机器上跑出来的命令（必须贴真实输出）

```bash
# 版本与编译信息
openssl version -a
openssl version -d          # 看 OPENSSLDIR 是不是 ~/rocopenssldir

# provider 架构（3.0 的核心变化，1.1.1 没有这条）
openssl list -providers -verbose
openssl list -cipher-algorithms | grep -i sm4

# 随机数
openssl rand -hex 16

# 哈希：SM3 标准测试向量 "abc"
printf "abc" | openssl dgst -sm3
#   期望 66c7f0f462eeedd9d1f2d46bdc10e4e24167c4875cf2f7a2297da02b8f4ba8e0

# SM4 加密（CBC + 全零 IV，仅实验用）
openssl enc -sm4-cbc -K 0123456789abcdeffedcba9876543210 -iv 00000000000000000000000000000000 \
  -in plain.txt -out cipher.bin
xxd cipher.bin | head

# SM2 生成密钥
openssl genpkey -algorithm EC -pkeyopt ec_paramgen_curve:SM2 -out sm2.key
openssl pkey -in sm2.key -text -noout
```

### 2.4 GmSSL 3.1.1

- 定位：国密算法专用库，覆盖 SM2/SM3/SM4/SM9/ZUC，命令行 `gmssl` 子命令风格（`gmssl sm3`、`gmssl sm2sign`、`gmssl sm4 -help`）
- 安装：脚本下载 `GmSSL-3.1.1-Linux.sh` 自解压到 `~/GmSSL-3.1.1-Linux`，然后写 `PATH`、`LD_LIBRARY_PATH` 到 `~/.bashrc`
- 验证：

```bash
gmssl version
printf "abc" | gmssl sm3
gmssl sm4 -help
```

- 常见坑：
  - `. ~/.bashrc` 只影响当前交互式 shell，`sudo` 下环境变量会丢 → 用绝对路径或写 `/etc/ld.so.conf.d/gmssl.conf`
  - 报 `error while loading shared libraries: libgmssl.so.3` → `LD_LIBRARY_PATH` 没生效
  - GmSSL 3 的 `sm3` 输出格式与 `openssl dgst -sm3` 不同，对比时要看清是 hex 还是 base64

### 2.5 OpenSSL 1.1.1 与 3.x 的差异（反思部分可用）

| 维度 | 1.1.1 | 3.x |
|:---|:---|:---|
| 算法加载 | ENGINE | Provider（default/legacy/fips/base） |
| 默认配置 | openssl.cnf | 多一层 `providers = ` 配置段 |
| 低层 API | 可用（MD5_Init 等） | 大量 deprecated，推荐 EVP |
| 国密支持 | SM2/SM3/SM4 有，但不完整 | 完整，且支持 SM2 签名带 Z 值预处理 |
| 命令 | `openssl enc -sm4-cbc` | 同左，但 `-provider legacy` 才能用部分老算法 |

## 四、我预判会卡住的点（先记下来，写 reflection.md 用）

1. **「密码」到底指什么**：口语和教材义的差别，一开始读第一章很别扭。
2. **对称加密够快了，为什么还要非对称**：第一反应是"多余"，其实卡在**密钥分发**上。
3. **MAC 和数字签名都防篡改，为什么签名还能防抵赖**：卡在"密钥是不是双方共享"。
4. **OpenSSL 3 的 provider 是什么**：1.1.1 的 ENGINE 还没搞明白，3.x 又换了一套。
5. **脚本为什么要动系统的 `/usr/lib`**：不理解"编译安装"和"包管理安装"的冲突。
6. **SM4 的 IV 和密钥都写死在命令里**：不知道这样做的后果（IV 复用 → 相同明文出相同密文）。

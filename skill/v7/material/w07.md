## 教材第10章（了解）

- 身份认证三要素：你知道的（口令）、你拥有的（USB Key / 智能卡）、你是谁（生物特征）；多因素认证 = 组合。
- 数字证书：把公钥和实体身份绑在一起的电子文件，遵循 X.509 v3；字段有版本、序列号、签名算法、颁发者、有效期、主体、主体公钥信息、两个唯一标识符、扩展、CA 签名。
- PKI 组件：CA（签发/管理/吊销，信任锚）、RA（审核身份）、证书库/目录服务、CRL（定期发布的黑名单）、OCSP（在线实时查询，补 CRL 的延迟）。
- 信任模型：层次（根 CA → 中间 CA → 终端）、网状、桥 CA；浏览器/系统的根证书列表就是信任锚。
- 证书生命周期：密钥生成 → CSR 申请 → 身份审核 → CA 签发 → 存储分发 → 使用 → 更新/吊销 → 归档。
- Windows 侧（本书特色，不能被通用 PKI 叙述盖掉）：证书存储区（MY / CA / ROOT / Trusted People，Current User 与 Local Machine 两套）、`CERT_CONTEXT` 结构、`CertOpenStore` / `CertFindCertificateInStore` / `CertGetCertificateChain`。

## 教材第11章（重点）

用 OpenSSL 从零搭私有 CA，走完整生命周期：

1. 根 CA：生成根私钥 → `openssl req -x509` 自签名 → 配 `openssl.cnf`；实践上根 CA 应离线保管。
2. 中间 CA：根 CA 签发中间 CA 证书，形成两级链。
3. 终端证书：申请方生成密钥对 → 生成 CSR（PKCS#10）→ CA 审核后用自己私钥签发 → 组装证书链。
4. 格式：PEM / DER 互转；PFX(P12) 把私钥和证书打包。
5. 吊销：`openssl ca -revoke` → 生成并发布 CRL。
6. 验证：链完整性、有效期、主机名（SAN）、吊销状态四件事。

## 我真实踩过的两个坑（旧稿里有）

### 坑 1：`openssl ca` 报 `failed to update database`

原因不是 cnf 写错，而是 **CA 数据库的三个文件与 cnf 里的 `dir` 对不上**：
`index.txt` 要存在且为空文件（不存在 ≠ 空）、`serial` 第一行是 16 进制序列号且要换行、
私钥要放在 `demoCA/private/cakey.pem`、并且要在 `demoCA` 目录下执行命令（因为 `dir` 是相对路径 `./demoCA`）。

### 坑 2：Chrome 导出的 PFX 用 `openssl pkcs12` 读报 `Mac verify error: invalid password?`

密码是对的。原因是新版 Chromium 导出 PFX 用的是 AES-256-CBC + SHA-256 这一代算法，
而老 OpenSSL（1.1.0 之前）只认 RC2/3DES；另一个方向也成立：**新 OpenSSL 读老 PFX 反而要 `-legacy`**。

# 7 轮迭代规划

> 目标：把「写每周预习报告」从 4 小时的手工活，压缩到「30 分钟审阅 + 少量补充」。
> 原则：**每一轮只解决一类问题**，且每轮都要能在 `output/vN/human-edited.md` 里找到"这一轮到底改好了没有"的证据。

| 轮次 | 触发（上一轮暴露的问题） | 本轮改动 | 验证方式 | 预期结果 |
|:---|:---|:---|:---|:---|
| v1 | 手写 4 小时，结构每次重排 | 7 节固定结构 + 每节写法 + 禁止编造 | 生成第 1 周稿并人工审阅 | 能出一份完整稿，但有 4 处事实错、2 处结构要求未执行 |
| v2 | v1 的要求 AI "看起来满足了" | 固定模板 + 字数区间 + 评分点映射表 + 对话轮次表格化 + 术语表 | 逐条核对 `feedback/v1-to-v2.md` 的 6 条修改要求 | 结构性问题归零，事实性问题减少但未归零 |
| v3 | v2 仍有"写深一点"这类不可判定表述 | 把每条要求改写成**验收条件**（含计数、正则、必须出现的字符串） | 我自己按验收条件逐条打勾，数 AI 是否真的满足 | 人工回改次数从 ~12 处降到 ~6 处 |
| v4 | v3 输出里仍有术语错（国密版 RSA、混淆 provider/ENGINE） | 引入教材术语表 + 术语纠错规则 + 禁用词表 | 用 grep 统计禁用词命中数 | 术语错误为 0，新增"术语自查"节 |
| v5 | v4 仍需人眼逐条查结构与禁用词 | `skill/v5/scripts/check.py`：结构/占位符/术语/Mermaid 语法/字数 | 脚本对 v4、v5 输出分别跑一遍 | 脚本一次报出 ≥5 个问题，其中至少 2 个是人审漏掉的 |
| v6 | 第 3 周起出现没有 Linux 实验的章节（Head First C、第 4 章重点 14 章） | 边界情况分支：无实验周、纯理论周、重点章/参考章、跨章周 | 用第 3、4 周真实输入试跑 | 无实验周也能写满 7 节，不出现"本节无内容" |
| v7 | 12 周要复制 12 次输入，配置易漂移 | `weeks.yaml` 配置化 + 一键生成 + 回归测试 | 一次生成 12 周，`check.py` 全部通过 | 单周耗时 ≤ 10 分钟（含审阅），12 周批量可复现 |

## 每轮的固定动作

1. 用上一版 Skill 写作 → 存 `output/vN/generated.md`（**不改一个字**）；
2. 逐条审阅、修改 → 存 `output/vN/human-edited.md`，每处改动写 `> [批注] 改动原因：…`；
3. 从批注里提炼**可复用**的问题 → 写 `feedback/vN-to-vN+1.md`；
4. 改 Skill → 存 `skill/vN+1/skill.md` + `changelog.md`；
5. commit（`[phase]` 格式）+ 打 tag `skill-vN`。

## 衡量"进化幅度"的指标（供 Phase 10 用）

| 指标 | v1 基线 | v7 目标 |
|:---|:---:|:---:|
| 人工批注条数 / 篇 | 5 | ≤ 2 |
| 事实性错误 / 篇 | 3 | 0 |
| 结构缺项 / 篇 | 2 | 0 |
| 单篇人工耗时 | 4 h（手工） | ≤ 30 min |
| 可复现性（换一章是否还能跑） | 需重写提示词 | 改一行 yaml |

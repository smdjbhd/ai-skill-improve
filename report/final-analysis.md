# 最终分析：v1 → v7 的进化幅度

这份分析只回答三个问题：

1. 七轮迭代到底改掉了什么？——用**同一个人、同一周（第 1 周）**的产出对比，不跨周比。
2. 哪些地方**没有**改掉？——这部分比成绩重要，也是 PEP 里"自我评估"的落点。
3. 如果现在把 v7 交给下一次预习，它到底能省多少、省不掉多少？

统计口径：v1–v7 的 `output/vN/human-edited.md`（人工改完、可提交的那一份）；汉字数剔除 `> [批注]` 行与代码块；
"日志引用"数是 `*.log:行号` 的出现次数；所有数字都可以用 `tmp/stats_v7.py` 重算。

## 一、量化对比（第 1 周，七版同题）

| 指标 | v1 | v2 | v3 | v4 | v5 | v6（第 9 周） | v7 |
|---|---|---|---|---|---|---|---|
| 总汉字（human-edited） | 2492 | 3852 | 4202 | 5645 | 5850 | 3202 † | 5847 |
| §2「AI 总结」汉字 | 484 | 978 | 996 | 1259 | 1217 | 908 † | 1233 |
| 人工批注条数 | 5 | 4 | 3 | 4 | 3 | 2 | 3 |
| 术语表行数 | 0 | 0 | 0 | 20 | 20 | 14 | 20 |
| 日志行号引用 | 0 | 3 | 27 | 27 | 27 | 0 | 27 |
| 可执行检查条目 | 0 | 0 | 12 | 18 | 19 | 21 | 21 |
| 检查脚本行数 | 0 | 0 | 0 | 0 | 577 | 749 | 1052 ‡ |

统计规则统一为：剔除 `>` 开头的行（批注与引用）与代码块后数汉字，与 `check.py` 的 C2 口径一致；
v7 的 §2 用 `check.py --week 1` 复核为 900–1300 之间（21 项 0 失败）。

† v6 是第 9 周（Head First C），与第 1 周不同题，只作"换周后仍能生成"的旁证，不参与"进化幅度"的结论。
‡ v7 含 `check.py` 701 + `course.py` 169 + `generate.py` 182 行。

### 三个最硬的数

1. **可核对的事实错误：3 → 0。** v1 的稿子里有三处硬错误（SM4 分组写成 64 位、SM2 说成"国密 RSA"、
   OpenSSL 3 写成"用 ENGINE"），v2 起被压到 0，v4 之后连"半个数值"（只说密钥长度不说分组长度）也判不合格。
   这是唯一一个**能被别人当面验伪**的指标，也是最该看的。
2. **人工批注：5 → 3，但性质变了。** v1 的 5 条里有 3 条是纠错（事实错）、1 条改导图、1 条补对话；
   v7 的 3 条全是"该深没深"（两章篇幅失衡、给了结论没给动作、GmSSL 参数差异没举例）——
   **错不出来了，只剩"浅"**。这比条数减少更能说明问题。
3. **检查条目：0 → 21，而且能自证。** v7 的 `--self-test` 用 4 个人为变异（删节名、换术语别名、
   改坏行号、改错分级）证明"检查器真的会失败"，不是打印 21 个 PASS 了事。检查一次 0.12 秒。

## 二、七轮各解决了什么（一句话版）

| 轮次 | 反馈里的一句话 | v 版做了什么 |
|---|---|---|
| v1→v2 | "凡是能数出来的规则都过了，凡是需要读进去判断的规则全糊了" | 固定模板、字数下限、评分点映射、真实性对照表 |
| v2→v3 | "模板对了但要求不可判定" | 每条要求带判定方法，C1–C12 |
| v3→v4 | "形状对了不等于内容对" | 术语唯一、术语表、数值三件套，C13–C18 |
| v4→v5 | "规则一条不省钱，也一条不省人" | 检查器进仓库，19 项一条命令 + 自测 + 覆盖率 |
| v5→v6 | "检查器把第一周写进代码里，换周全红" | 三套 profile、三态结果（PASS/FAIL/N/A）、C19 分级 |
| v6→v7 | "三种周是代码里的三个字典，不是课程表" | `weeks.yaml` + `course.py` + `generate.py`，`--week` 必填 |

七轮里有五轮（v3、v4、v5、v6、v7）的改动**都不是"写得更好"，而是"把含糊的要求变成能验的东西"**。
这也是这门课"Skill 迭代开发"真正想练的事：不是让 AI 一次写对，而是让下一次的失败**有名字**。

## 三、没改掉的部分（诚实清单）

1. **反思、批注、真实卡壳，一条都没法代写。** v7 仍然要求我把"我哪一步卡住了、当时希望 AI 怎么帮"
   亲手写进 §3 和附录 A；检查器只能查"有没有引用原句、有没有更正"，查不出"这是不是你真想过的"。
   按我的估算，v7 能覆盖一次预习 70%–80% 的体力活（排版、术语、数值、行号、导图、自检），
   剩下 20%–30% 全是它不该碰的。
2. **12 周里只有 2 周有素材。** `generate.py --all` 的输出是"能生成 2 周，素材不足 10 周"。
   这证明的是"缺素材会报错、不会编"，**不是"另外 10 周也能写"**。要说 v7 泛化得好，
   还差 10 份 `material/wNN.md`。
3. **`c-crypto` 形态没有真报告。** 第 4 周我只放了分级夹具，因为我对教材第 14 章没有原文，
   硬写就得编节名页码。所以"混排周"这条路径只有单元级证据（形态判定 + C19 三档），没有端到端证据。
4. **检查器只认我自己定的格式。** 七节标题、`<!-- 目标字数 -->`、`$ ` 开头的命令行、`> AI 原话｜`——
   这些约定都是 v3–v7 自己长出来的，换个老师给模板，21 条得重写一半。
5. **批注数从 5 降到 3，但没到 0，也不该到 0。** 到 0 意味着"AI 写的我一个字都不用改"，
   那我交的就不是我的作业了。

## 四、如果现在就用 v7（下一次预习的流程）

```
1. 读教材，把要点写进 skill/v7/material/wNN.md（这一步不能省，约 40 分钟）
2. python skill/v7/scripts/generate.py --week N --out output/wNN.md     # 10 秒，产骨架
3. 按素材把 §2 写满，§3/§5/§6 用真实卡壳与真实日志填（约 30 分钟）
4. python skill/v7/scripts/check.py --report output/wNN.md --week N      # 0.12 秒，21 项
5. FAIL 的按行号改；N/A 的在附录 D 写明"这周不适用"
6. python tools/render_mermaid.py output/wNN.md output/wNN.png           # 导图
```

对比第 1 周手工的 4 小时：第 3 步的"写"还是要 30–40 分钟，但第 1 步之后**没有一次"排完版发现又错一处"**。
省下来的不是写字时间，是返工时间。

## 五、结论

- 七轮的最大产出不是那份报告模板，是**"要求 → 判定方法 → 可执行检查 → 自测证明它会失败"**这条链。
  这条链让"下一版比上一版好"变成可验证的，而不是我说好就好。
- 最大的遗留问题也不是技术问题，是**素材**：`material/wNN.md` 只有 2 份，
  v7 的泛化能力目前只是"设计上泛化"，不是"跑过 12 周"。
- 如果只允许留一句话给下一个做这个作业的人：**别急着让 AI 写正文，先让它把"怎么算写完"写清楚。**

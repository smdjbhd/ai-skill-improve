## 三、写的时候最想要 AI 帮我什么（按渴望程度排序）

> 这一节直接决定 Skill 的功能边界。写具体动作，不要写"帮我写作业"。

| 想要的帮助 | 具体场景 | 后来 Skill 里对应哪条规则 |
|:---|:---|:---|
| 帮我把章节内容压成结构化提纲 | 读完第 1 章脑子里是散的，不知道怎么串 | |
| 帮我把术语核对一遍 | 怕把 SM4 分组长度、SM2 类型写错 | |
| 帮我想苏格拉底问题怎么追问 | 自己提问容易跳步，一问一答接不下去 | |
| 帮我把报错整理成"现象-排查-解决" | 排查完就忘了，写的时候想不起命令 | |
| **不要**帮我编实验输出 | 终端里没跑过的命令，写进报告就是造假 | |

## 四、哪些部分我坚持不让 AI 写

> 这段是自我约束，也是后面每轮审阅的底线。

- 苏格拉底对话里的「我」的回答：必须是我真的答错的版本，AI 代答就失去意义；
- 问题与解决里的报错和命令：必须是终端里真实出现过的；
- 反思与补充里「我的补充」：AI 不会知道我哪句话没读懂。

## 五、从手工经验到 Skill 的抽象（Phase 2 的输入）

> 手工写完后回填。左边是手工时反复做的动作，右边是能不能固化成规则。

| 手工动作 | 出现次数 | 能否固化 | 固化方式 |
|:---|:---|:---|:---|
| 翻评分要求核对有没有漏节 | 每份 3 次 | 能 | 固定章节骨架 |
| 检查术语（SM4/SM2/SM3 参数） | 每份 5+ 次 | 能 | 术语表 + 禁用表述 |
| 调 Mermaid 语法 | 每份 2-3 次 | 部分 | 给定可用的 mindmap 模板 |
| 想苏格拉底追问 | 每份 10+ 轮 | 不能 | 只给追问策略，不给答案 |
| 整理报错成四段式 | 每份 2 次 | 能 | 四段式模板 |
